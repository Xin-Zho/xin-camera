# 时间轴几何统一（M13）

地图右侧那条竖向时间轴，之前在真机上是「底部对齐、越往上越偏」。
这一篇记的是根因、修法、验证边界，以及**还没真机确认**的部分。

## 1 现象

滑动块与刻度在底部基本重合，越往顶部偏移越明显。
删故事 / 恢复故事本身没问题（那是 M12 的内容），偏的是几何。

## 2 根因：三套坐标系

同一个「ratio → 纵向位置」被三个地方各自算了一遍，而且算的不是一个东西。
设轨道整体高度 `H`、上下内缩 `inset`（= `spacing.lg` = 16px）：

| 谁 | 用的公式 | 实际行程 | 锚点 |
|---|---|---|---|
| 竖线 `trackLine` | `top/bottom: 16`（像素） | `[16, H-16]` | 轨道顶 / 底边 |
| 刻度 marks | `bottom: ratio × 100%` | 见下 | 轨道底边 |
| 滑动块 + 拖动 | `translateY(-ratio × H)`，H 来自 `onLayout` | `H` | 轨道底边（滑块中心） |

关键在刻度的百分比按**哪个盒**解析，两边不一样：

- **原生端**：RN 的 `layoutTree` 统一用 `YGErrataAll` 配置 Yoga——
  `react-native/ReactCommon/react/renderer/components/view/YogaLayoutableShadowNode.cpp`
  里 `configureYogaTree(..., YGErrataAll /*defaultErrata*/, ...)`；
  其中 `AbsolutePercentAgainstInnerSize` 让百分比按**内容盒**解析
  （`AbsoluteLayout.cpp`：`containingBlockHeight = absoluteErrata ?
  containingNodeAvailableInnerHeight : 测量高度 - 边框`）。
  所以刻度的行程是 **`H - 2 × inset`**。
- **Web 端**：CSS 的 `bottom: %` 按 **padding 盒** 解析，行程是 `H`。

而滑块和拖动一直用 `onLayout` 拿到的**整个** `H`。
于是原生端两条曲线都锚在底边：

```text
偏差(ratio) = ratio × H − ratio × (H − 2·inset) = ratio × 2·inset
```

`ratio = 0`（最早）时 0，`ratio = 1`（最新）时 32px，中间线性。
这正是「底部重合、越往上越偏」，而且**只有原生端会偏**——Web 端反而对得上，
所以这个问题在浏览器里复现不出来。

顺带还有两个小问题：

- 刻度的两端本该落在竖线的两端上，实际超出去了 `inset`（16px）；
- 滑块靠 `bottom: 0` + `marginBottom: -size/2` 把**中心**摆到底边，
  再减 `ratio × H`。「中心 vs 边缘」的补偿和「行程」混在一个表达式里，
  任何一处改了都会牵动另一处。

## 3 修法：一个纯函数，三处共用

新增 `src/components/timeline/railGeometry.ts`（纯函数、零 import）：

- 起点 = 轨道顶部内缩 `RAIL_INSET`，终点 = 底部内缩 `RAIL_INSET`，
  有效高度 `railSize = max(0, H − 2 × inset)`；
- 刻度、滑块、拖动**一律像素**，不再出现任何百分比定位；
- `centerFromBottom(ratio, H)` 给出刻度/滑块中心离轨道底边的距离；
- `tickBottom(...)` = 中心 − 刻度槽半高（槽高 `TICK_SLOT`，槽内居中放那一小条，
  粗细三种刻度共用同一个中心点，不必各算一次半高）；
- `thumbTranslateY(...)` = 中心 y − 滑块半高（滑块布局改成 `top: 0`，
  「中心 vs 边缘」这一项就摆在这里，不再跟负 margin 纠缠）；
- `ratioForTouchY` 与 `touchYForRatio` 互为逆映射，拖动与显示同源。

触摸映射只在竖线区间内定义，两端之外夹取到边界（不再甩到另一端）。

**改过的文件只有两个**：新增 `railGeometry.ts`，改写 `TimelineRail.tsx`
的刻度排版与滑块位移。地图摘要、可见性、删除/恢复逻辑一行没动。
底部留白（`bottom: 112`，避让地点卡片）、空态（一张可见照片都没有时不画滑轨）、
日期范围收敛都保持原样。

两个附带变化：

- 滑块现在完全落在轨道卡片**里面**（以前中心压在底边上，半个滑块探出圆角外）；
- 刻度不再超出竖线两端，早/晚两格刚好贴着线的端点。

## 4 验证

### 已做（自动化）

- `tsc --noEmit` 零错误。
- 新增 `test-rail-geometry.mjs` **967 条**，每条都按**顶部 / 中部 / 底部**三点查，
  不是抽查中间值：
  - 刻度与竖线两端对齐（单刻度时的落点单独一条）；
  - 刻度中心与滑块中心在每一个索引上都重合；
  - 刻度槽的中心 = 刻度线；
  - 滑块完整落在轨道盒内（`top ≥ 0 && bottom ≤ H`）；
  - 正向映射与逆向映射一致：`y → ratio → y`、`ratio → y → ratio`；
  - 索引 ↔ ratio 互为逆映射；
  - 拖动时手指位置 = 滑块中心；
  - 越界夹取（顶部以上、底部以下、NaN、±Infinity 都不越界）；
  - 退化高度（0 / 10 / 31 / 32）不出 NaN，高度不够时不响应而不是把索引甩到 0；
  - 单调性与等间距；
  - **根因留档**：把两条旧公式并排算一遍，锁定「底部 0、中部 `inset`、顶部 `2·inset`」
    这个特征，防止有人把百分比写回去。
- 其余 7 个套件全部重跑通过（状态机 91、存档 38、导入落库 73、相册读取 84、
  日期口径 154、导入规划 122、可见性 108），**合计 1637 条**。
- `expo export --platform web` 退出码 0，`map-*.js` 正常产出。

### 没做（必须真机）

- **没有真机 / 模拟器可用，也没有跑过 Web 预览。** 时间轴只在地图页出现，
  而地图页依赖 `react-native-maps`，这个库**没有 Web 实现**
  （本地起 dev server 直接 `codegenNativeComponent is not a function`，
  页面 500），所以浏览器里连这张页面都渲染不出来。
- 上面 967 条断言的是**几何数值**，不能替代看一眼：
  需要真机确认的是这些点
  1. 底部 / 中部 / 顶部三处，滑块中心是否压在刻度线上；
  2. 拖动跟手（手指位置 = 滑块中心），松手吸附到最近刻度；
  3. 竖线两端与最早 / 最晚刻度是否贴齐；
  4. `'worklet'` 标记在真机上不报错（`railGeometry` 里每个函数都标了，
     少标一个会在 UI 线程崩）；
  5. 横竖屏切换 / 键盘弹出导致轨道高度变化后，刻度是否跟着重排。
- 顺便要验的既有行为：日期切换、拖动、删故事、恢复故事——
  这次没碰它们的逻辑，但改了滑块位移，值得顺手走一遍。

## 5 已知限制

- `RAIL_INSET` 写死 16，没有按轨道高度自适应；轨道特别矮（< 32px）时
  有效高度为 0，此时拖动不响应（断言里有覆盖），界面上不会给提示。
- 刻度槽宽固定 16px，选中的刻度（16px 宽）刚好撑满；再宽的刻度样式要改这个常量。
- 触控映射把「手指位置」当「滑块中心」，手指落在两端内缩区时会夹取到边界，
  滑块会停在离手指最多 `inset + 半高` 的位置——这是内缩滑轨的常规做法，
  不是 bug，但要接受这个手感。
