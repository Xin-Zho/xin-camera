# xin-camera

iPhone 回忆 App —— 第一阶段可交互原型。

按地点与时间组织照片记忆：地图 + 竖向时间轴浏览地点，点开地点看到访卡片堆叠，
再进到那一次到访的图库；另一条线是杂志式的「故事相册」。

- 技术栈：Expo SDK 58 · React Native 0.88 · TypeScript · Expo Router · react-native-maps · Zustand
- 开发机：Windows；预览：iPhone + Expo Go
- 数据：全部为本地 mock（24 张项目内示例图），不接真实照片库 / GPS / 后端 / AI

## 跑起来

```powershell
cd D:\xin-camera
npx expo start
```

iPhone 与电脑连同一个 Wi-Fi，用 Expo Go 扫终端二维码。
Android / iOS / Web 之外的平台没有验证过，Web 上地图不可用（react-native-maps 无 web 实现）。

> 注意：本项目是 **SDK 58**。手机上的 Expo Go 必须支持 SDK 58，
> 否则会提示版本不兼容，此时请升级 Expo Go。

## 本地持久化

**只存 `stories`**，`places` / `visits` / `media` 每次从示例数据重建。原因是原型里用户能改的只有故事这一层；
而 `MediaAsset.uri` 现在是 `mock:<slug>` 键，跟着素材表走，存下来反而会在改名后变空图。接真实相册时
这三层才需要一起存，那时 uri 是真路径，语义也变了。

- 存档键 `xin-camera-store`，版本 `STORE_VERSION = 1`，改结构时版本 +1 并在 `migrate` 里补一条。
- **进存档的**：`stories` 全量，含 `isDeleted`、`mergedFromStoryIds`、`mergeSnapshot`。
  `mergeSnapshot` 必须一起存——不然重启后合集还在但拆不回去了。
- **不进存档的**：`timeRange`、`selectedPlaceId`、`selectedVisitId`、`lastMergedStoryId`。
  这些是瞬态 UI 状态，重启回到"最近一次回忆所在月份"比恢复上次拖到的位置更符合预期。
- **结构校验**：`merge` 时逐条过 `isValidStory`（id / title / mediaIds / placeIds / startAt 必须齐）；
  一条都留不下就当存档坏了，整体回退示例数据——空相册比丢一次编辑更糟。
- **启动不闪**：`app/_layout.tsx` 等 `persist.hasHydrated()` 再渲染路由树，另设 1.2s 兜底，
  避免"存档还没读完先按示例数据画一帧"导致改过的标题闪回旧值。
- **存不了也不崩**：`safeStorage` 把 AsyncStorage 的读写都包了 try/catch，原生模块缺失时降级为内存态
  并打一条 warn，不让启动流程抛错。
- 重置入口在设置页底部（`resetToMock`，带二次确认），重置后存档立刻被示例数据覆盖。

### 存档坏了怎么办

两种失败要分开，因为用户能做的事不一样：

| 情况 | 判定位置 | 界面 | 数据 |
|---|---|---|---|
| 存储不可用（原生模块缺失等） | `safeStorage` 抛错 / 读取失败 | 设置页红条：**当前修改仅在本次运行有效** | 无法保存，退出即回到示例数据 |
| 存档不是合法 JSON | `safeStorage.getItem` 预解析失败 | 设置页黄条 + 「查看备份」 | 原样抄到 `xin-camera-store__quarantine`，本次用示例数据 |
| JSON 合法但一条可用故事都没有 | `merge` 校验后为空 | 同上 | 同样备份原始文本 |

关键点：**坏存档不能被示例数据直接覆盖**。如果什么都不做，zustand 回退到示例数据后，
下一帧 `persist` 就会把整份坏存档写成新的示例 JSON，用户攒的标题和合并记录彻底没了。
所以 `getItem` 在把 `null` 返回给 persist 之前先抄一份到隔离区，隔离区只有 `quarantine.tsx`
页面的「删除这份备份」能清掉。备份存的是**原始文本**，不是解析后的对象——后者已经是"我们以为它是什么"。

## 真实相册读取（只读实验）

独立入口（故事页右上角「相册」/ 设置页），和示例数据那条线完全隔离：不写 store、不生成到访和故事、
不修改相册。删掉 `app/library/` 和 `src/library/` 不影响主流程。

- 用 SDK 58 的**类式 API**（`Query` / `Asset`）。`expo-media-library/legacy` 从默认入口导入会**运行期抛错**，不是警告。
- 列表页一次拿全的只有「时间和类型」：`Query.exeForMetadata()`。**定位和缩略图必须逐条补**
  （`Asset.getLocation()` / `Asset.getUri()`），所以页大小固定 24，第一页自动读、后续每页用户点。
- **`creationTime` 是毫秒，但类型注释写的是秒。** iOS 实现 `Date.millisecondsSince1970` 才是真的。
  处理方式是原值照存 + 按数值量级判定单位（`src/library/epoch.ts`），界面把原始值和判定结果一起显示。
- **相册 API 不提供拍摄地时区。** `getLocation()` 只有经纬度；只有 EXIF 里可能残留
  `OffsetTimeOriginal`，且读取代价高（导出临时文件 + 可能触发 iCloud 下载）。详见 `docs/v2-photo-library.md`。
- 权限分六档：未决 / 全部 / 部分 / 已授权但宿主不区分范围 / 拒绝 / **原生模块缺失**。
  最后两档在界面上是两回事，不能混成"没有权限"。

## 地图聚合

- 判据是**屏幕上两个标记的像素距离**（`CLUSTER_RADIUS_PX = 52`），不是经纬度阈值。
  放大到一定程度自然散开，不需要维护"缩放级别"状态。
- 聚合标记只显示**地点数量**，不叠加到访数——两个数字挨在一起会分不清哪个是地点数。
- 三种时段状态：全部有照片＝实心深色，部分有照片＝强调色描边，全部无照片＝灰色描边并整体变淡
  （变淡走 `Marker` 原生 `opacity`，不触发视图重绘）。
- 点击聚合：能放大就 `animateToRegion` 放大到成员占视口 62% 的位置；放大也分不开
  （坐标几乎重合，或已到 `MIN_REGION_DELTA` 下限）就弹地点列表。
- "放大后能否分开"是用**同一套聚合函数模拟一次**得出的，不是另写一套阈值判断。
- 入场动效只在标记**挂载**时播一次：`key` 由成员构成决定，所以平移地图、切换时间轴
  都不会重新挂载 → 不会重播；只有缩放导致拆开/合并时才会有一次。

## 阅读页的图片尺寸

单张大图按"一屏看全"的偏好来定尺寸（注意：页面本来就能滚动分段看完长图，这里缩小是为了不必滚动）：

- 不依赖 `aspectRatio` 反推高度，直接给显式像素宽高；
- 盒子 = 内容宽 × 屏幕可视高的 52%（`maxReaderMediaHeight`）；
- 图片按 contain 语义等比缩进盒子（`fitWithin`）：横图铺满整宽，竖图缩到盒高以内并水平居中；
- 竖图在小屏上会比原来窄一些、两侧留白，这是预期；
- 半宽格子里的竖图高度由真实宽高比算出，不再用固定的 1.3 倍近似值。

52% 是**原型默认值**，不保证标题多行 + 正文时一定一屏放得下。若真机上仍遮挡，
应改为测量图片上方实际占用、按可用高度计算，而不是反复调这个比例。

> `cover` 是否裁切只取决于容器与原图的宽高比是否一致，与图片元数据是否正确无关——
> 元数据一致只说明比例算得对，不能推出"一定不裁"。

## 整理的约定

- 列表右上角「选择」或长按任意一本进入多选；选中 ≥2 本可合并，选中 ≥1 本可删除。
- 合并标题由 store 自动生成（`地点 · 起止日期`），不弹输入框打断操作；进合集后可在编辑页改。
- 合集 id 用「时间戳 + 自增序号」，只用时间戳会在同毫秒连续合并时撞 id，导致合集指向自己。
- 删除是软删除：`isDeleted = true`，对象、照片、地点都不动；删完自动展开「已删除」区，恢复入口当场可见。
- 拆分必须确认，因为按合并前快照还原，**合并之后在合集里做的修改会丢弃**。
- 合并可以嵌套（合集再与第三本合并），拆分按层还原。

## 编辑页的约定

- 所有修改都走 `appStore` 的语义化 action（`setStoryTitle` / `setStoryCover` /
  `moveStoryMedia` / `setStoryLayout` / `setStoryCoverTitleMode` / `setStoryText` /
  `toggleHighlightedMedia`），页面不直接拼 patch 写 store。
- 校验在 store 层：空标题、不属于本故事的封面、越界的移动一律被拒。
- 文本输入用本地草稿 + 260ms 延迟提交，卸载和「完成」时都会 flush。
- 改动即时保存，没有"保存 / 取消"的歧义。

## 回归时踩到的两条硬约束

- **tab 页里不要叠加 `insets.bottom`。** `BottomTabView` 是 column 布局，tab bar 作为最后一个
  子节点真实占位，内容区高度已经把 tab bar 挖掉了；再用 `useSafeAreaInsets().bottom` 加一次，
  等于把安全区算两遍——表现是底部卡片凭空浮高、操作条底部多一条空白，而且卡片会压住右侧
  时间轴的下段（那一片正是最早的时段）。地图卡片与滑轨、故事页操作条都按这条改过。
- **时间轴松手回调可能早于本次时段的重渲染。** `Gesture.Pan().onEnd` 里的 `runOnJS` 用的是
  当前闭包，那时组件里的 `summaries` 还是上一个时段的派生结果。凡是在手势回调里要用筛选结果，
  都按 tick 自己的 `range` 现算一次，不要读组件里的派生值。

## 已知限制

- 持久化**只覆盖故事层**：`places` / `visits` / `media` 每次从示例数据重建。好处是改素材不影响存档，
  代价是接真实相册时必须一起改存档结构（版本 +1 + 迁移），不能直接沿用 v1 的存档。
- 存档是**全量覆盖写**，没有节流。故事多到几百本时每次编辑都会重写一遍完整 JSON；
  当前示例规模无所谓，量级上来要改成只写变动或加 debounce。
- 合并只有一步到位的「合并」，没有二次确认，也没有 undo 栈；误合并要到阅读页拆开。
- 选中地点后没有主动收起底部卡片的入口（点另一个地点或进详情才会变）。
- 聚合半径固定 52px，不随标记疏密自适应；地点重合时只给列表，不做"蜘蛛网"散开。
- 时间轴只支持按月吸附，年 / 日粒度的自适应浏览还没做。
- 照片排序用上下箭头，不是拖拽。
- 合集标题只能自动生成，界面上没有让用户直接输入合集名的入口（可进合集后在编辑页改）。
- 拆分按合并前快照还原，合并后在合集里做的修改会丢弃（确认弹窗已说明）。
- 时间轴松手后的地图跟随一次只挑「当前时段到访最多」的一个地点，跨城市时不会一次展示全部。
- 编辑页的键盘避让未在极小屏（SE 尺寸）上验证过。
- 大图没有「点开看全屏」，尺寸上限固定为半屏高，短屏设备上竖图会明显变小。
- 标记入场动效依赖 `Marker` 内部视图动画。react-native-maps 是把标记栅格化成图片显示的，
  真机上可能看不到动画（此时会退化成直接出现，不会停在半透明或缩小状态）。
- iPad 分屏未验证：`VisitCardStack` 和到访图库的格子尺寸用的是模块级 `Dimensions` 常量。

真实相册那一侧的限制（这一轮只到"能读"，还没进主流程）：

- **缩略图会触发 iCloud 下载。** `Asset.getUri()` 的 `isNetworkAccessAllowed` 是 `true`，
  iCloud 上的资产第一次进列表会真的开始下载原图。现在只靠页大小 24 + 并发 3 + 手动翻页压着。
- **列表显示的是原尺寸图。** 新版 API 没有缩略图接口，只能把原图 URI 交给 `<Image>` 让它降采样，
  24 张 48MP 的图同时解码仍有内存压力。后续要在原生侧按 `targetSize` 出缩略图。
- **视频没有缩略图**，只给类型角标和时长。
- **`Query` 没有 count 接口**，界面只显示「已加载 N 张」，不显示总数。
- **没有定位的照片归属没处理**：读取页面只标注「无定位」，还没决定它们该进哪个地点。
- **Expo Go 里用的是它自己的权限文案**，`app.json` 里配的 `photosPermission` 只在自建构建生效。

- **时间只按设备本地时区拆年月日。** 示例数据钉在 `+08:00`，展示层却直接走 `Date.getMonth()` /
  `getDate()` / `getHours()` 这些**本地**读法，所以设备时区不是 +08:00 时**会跨日**：
  `2026-09-28T06:44+08:00` 在 UTC-8 的设备上会显示成 9 月 27 日。列表的「今天 / 昨天」也拿
  设备当前时间去比，会跟着错位。时间戳排序本身不受影响，但会出现「同一天的照片被拆进两个分组」。

## 待定口径（接真实相册前必须定）

**照片按拍摄地日期还是按当前所在地日期分组。**

这一条不是显示细节，它决定三样东西跟着哪个日期走：时间轴的刻度边界、列表的「今天 / 昨天 /
10月12日」分组、默认标题 `地点名 · 到访日期`。今天这几处都读同一套 `src/utils/datetime.ts`
的本地时区拆分，所以换口径等于换这一层的输入，不是各页各改。

两种口径的实际差别：
- **拍摄地日期**（照片自带的拍摄地时区）：回忆的日期永远和当时一致，回国后看旧照片不会串位。
  代价是本地日期的边界不唯一——同一天的照片可能来自两个时区，「今天」需要按每张照片各自算。
- **当前所在地日期**（设备时区）：分组边界简单一致，但旅行照片在回国后日期可能整体前移一天，
  和当时的记忆对不上。

倾向是拍摄地日期，理由是这东西卖的是「回味当时」，日期错一天是硬伤；但这要等接入真实相册、
确认 `PHAsset` 是否稳定给出拍摄地时区之后再定。接入时先只验证权限、拍摄时间、定位三样，
把日期归属的口径实验单独做一轮，不要塞进同一批改动。

**2026-10-26 补充（已核对，结论是坏消息）**：相册 API **不提供**拍摄地时区。
`Asset.getLocation()` 只给经纬度；`creationTime` 是绝对时刻，时区信息在它里面本来就不存在；
唯一可能残留线索的是 EXIF 的 `OffsetTimeOriginal`，而截图和社交软件保存的图片基本没有，
读取还要把原图导一遍。所以「拍摄地日期」这个口径**没有可靠的系统级输入**，
口径实验要先解决"拿不到时区时退化成什么"，可选退路：

1. 有 EXIF 偏移就用它，没有就退回设备时区（明确标注"这条按设备时区算"）
2. 用定位坐标反查 IANA 时区（需要离线时区边界数据，另算一笔依赖）
3. 干脆统一按设备时区，接受"回国后旧照片前移一天"

这三条要在口径实验里用真实相册样本量一遍命中率再选，不要先写死在代码里。
